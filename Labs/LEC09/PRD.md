# 소닉 애니메이션 뷰어 — 개발 문서 (PRD)

근거: `PRE_PRD.md`

## 1. 개요

### 1.1 목표

`sonic-sprite.png`에 들어 있는 소닉의 동작 10종(76프레임)을 순서대로 자동 재생하는 뷰어를 만든다.
사용자가 아무 입력을 하지 않아도 모든 동작이 반복과 정지를 거쳐 끝없이 순환한다.

### 1.2 범위

| 포함                               | 제외                                        |
| ---------------------------------- | ------------------------------------------- |
| 모든 동작을 자동으로 순서대로 재생 | 키 입력으로 동작 고르기 (LEC10에서 다룸)    |
| 동작별 5회 반복 후 1초 정지        | 사운드, 배경 스크롤                         |
| 2배 확대 출력, 상태 정보 표시      | 점프처럼 위아래로 움직이는 것               |
| 이동 동작은 재생하면서 좌우로 이동 |                                             |
| ESC와 창 닫기로 종료               |                                             |

## 3. 사용자 시나리오

1. 프로그램을 실행하면 800×600 창이 열리고, 화면 중앙에서 1번 동작(대기)이 2배 크기로 재생된다.
2. 대기 동작이 11프레임을 5번 돌고 나면, 마지막 프레임에서 1초 동안 멈춘다.
3. 이어서 2번 동작(걷기)이 재생된다. 걷기는 발을 움직이면서 화면 오른쪽으로 걸어가고, 화면 끝에 닿으면 몸을 돌려 반대쪽으로 걸어간다. 이렇게 10번 동작(포즈)까지 진행된다.
4. 10번 동작의 정지가 끝나면 다시 1번 동작부터 시작한다.
5. 화면 위쪽에는 지금 몇 번째 무슨 동작인지, 몇 번째 반복인지, 몇 번째 프레임인지가 표시된다.
6. ESC를 누르거나 창 닫기 버튼을 누르면 프로그램이 끝난다.

## 4. 기능 요구사항

### F1. 화면 출력

- 캐릭터는 원본의 **2배**로 그린다. 가장 큰 프레임(40×45)은 80×90이 된다.
- 위치 기준은 **몸 중심선**(x = 캐릭터 위치 `pos_x`)과 **발 기준선**(y=200)이다. 제자리 동작에서 `pos_x`는 400(화면 가운데)이다.
  - 그리는 중심 x = pos_x + dx × 2 × 방향 (dx는 프레임마다 정한 가로 보정값, 5.1 참고. 방향은 오른쪽 1, 왼쪽 -1)
  - 그리는 중심 y = 200 + (프레임 높이 × 2) / 2
  - 이렇게 하면 프레임 너비와 높이가 달라도 몸은 좌우로 흔들리지 않고, 발은 같은 높이에 놓인다.
- 매 화면마다 `clear_canvas()`로 지운 뒤 그리고, `update_canvas()`로 보여 준다.

### F2. 동작 재생

- 시트의 **한 줄 = 한 동작**이다. 프레임은 왼쪽에서 오른쪽 순서로 재생한다.
- 프레임 간격은 **0.1초**(초당 10프레임)로 시작한다.
  - 실행해서 보고 너무 빠르거나 느리면 조정한다. 조정한 값과 이유는 커밋 메시지에 적는다.
- 시간은 `delay()`를 쌓아서 재지 않고, `get_time()`의 **실제 경과 시간**으로 잰다.
- 창을 끌어서 잠시 멈췄다가 풀리면 경과 시간이 크게 튈 수 있다. 이때 프레임이 한꺼번에 몰아서 넘어가지 않도록, 한 번에 많아야 1프레임만 넘긴다.

### F3. 반복과 정지

- 마지막 프레임까지 재생하면 반복 1회로 센다.
- **5회**를 채우면 **1초 동안 정지**한다.
  - 정지하는 동안에는 그 동작의 **마지막 프레임**을 그대로 보여 준다.
  - 정지 중에도 화면 갱신과 이벤트 처리는 계속한다. 그래야 창이 멈춘 것처럼 보이지 않고, ESC도 바로 먹힌다.
- 정지가 끝나면 다음 동작의 첫 프레임, 반복 1회차부터 시작한다.

### F4. 전체 순환

- 10번 동작의 정지가 끝나면 1번 동작으로 돌아간다. 프로그램을 끌 때까지 계속 반복한다.
- 프레임 간격 0.1초 기준으로 한 바퀴는 약 48초다. 재생 38초에 정지 10초를 더한 값이다.

### F5. 상태 표시

화면 왼쪽 위에 두 줄로 표시한다.

```
[2/10] 걷기   반복 3/5          ← 정지 중이면 "반복 5/5 (정지)"
프레임 7/12   크기 26x39
```

### F6. 이동

- 시트의 그림은 모두 오른쪽을 보고 있다. 아래 **이동 동작**은 프레임 재생과 **동시에** 화면에서 좌우로 움직인다.

| 동작 | 이동 속도 (화면 픽셀/초) |
| ---- | ------------------------ |
| 2 걷기 | 100 |
| 3 가속 | 180 |
| 5 구르기 | 300 |
| 6 달리기 | 260 |
| 7 대시 | 400 |

- 나머지 동작(대기, 몸 말기, 뒤돌기·피격, 정면 달리기, 포즈)은 화면 가운데에서 제자리 재생한다.
  - 정면 달리기는 화면 쪽을 보고 뛰는 그림이라 좌우로 움직이지 않는다.
- 위치는 프레임이 바뀔 때만 옮기지 않고, **매 루프마다 실제 경과 시간 × 속도**만큼 옮긴다. 프레임이 바뀔 때만 움직이면 0.1초마다 뚝뚝 끊어져 보인다.
- 창을 끌었다 놓아 시간이 크게 튀어도 순간 이동하지 않도록, 한 번에 옮기는 시간은 많아야 `FRAME_TIME`(0.1초)으로 제한한다.
- 몸 중심이 화면 양쪽 끝에서 `MOVE_MARGIN`(60픽셀) 안쪽에 닿으면 **방향을 반대로** 바꾼다.
  - 왼쪽으로 갈 때는 그림을 좌우로 뒤집어(`clip_composite_draw`의 `'h'`) 그리고, dx도 반대로 적용한다.
- 동작이 바뀌면 화면 가운데(x=400)에서 오른쪽을 보고 시작한다.
- 1초 정지하는 동안에는 위치도 멈춘다.

### F7. 종료

- `SDL_QUIT`(창 닫기)나 `SDLK_ESCAPE`가 들어오면 메인 루프를 끝내고 `close_canvas()`를 호출한다.

## 5. 프레임 데이터

### 5.1 좌표 규칙

- `clip_draw(left, bottom, w, h, x, y, w*2, h*2)`로 그린다.
- `bottom`은 이미지 **아래쪽**부터 센 값이다. 이미지 위쪽 기준 y를 쓰면 `bottom = 525 - top - h`이다.
- 같은 줄의 프레임은 모두 같은 `bottom`과 `h`로 자른다. 프레임마다 너비(`w`)만 다르다.
  - 이렇게 해야 프레임이 바뀔 때 발 위치가 위아래로 흔들리지 않는다.
- 프레임 너비는 팔다리 모양에 따라 달라서(걷기는 24~37), 프레임 가운데에 맞춰 그리면 몸이 좌우로 흔들린다.
  - 그래서 프레임마다 **가로 보정값 dx**를 둔다. dx는 원본 픽셀 단위이고, 그릴 때 2배 한다.
  - dx = (프레임 가운데 x) − (몸 중심 x)
  - 몸 중심 x는 프레임 위쪽 절반(머리와 몸통)에 있는 불투명 픽셀들의 가로 평균 위치다. 팔다리는 많이 움직이므로 기준에서 뺀다.
  - 몸이 프레임 가운데보다 왼쪽에 있으면 dx가 양수가 되고, 그만큼 오른쪽으로 옮겨 그린다.
  - 예외: 4번(몸 말기)과 5번(구르기)은 공 모양으로 도는 동작이라 위 절반의 위치가 프레임마다 바뀐다. 프레임 상자가 곧 공의 테두리이므로 dx를 0으로 두어 공의 중심을 맞춘다(구현 16·17단계에서 확인: 4배 화면 기준 흔들림 14픽셀 → 2픽셀).
  - 구현하면서 직접 보고 고친 값: 6번(달리기) 1·2번 프레임과 7번(대시) 전체. 앞으로 뻗은 흰 장갑과 8자 다리 잔상 때문에 계산값으로는 머리가 오른쪽으로 치우쳐서, 머리 위치를 재서 다시 정했다(7번의 1·2번은 6번의 1·2번과 같은 그림이라 같은 값).

- 맨 위의 제목 글자와 맨 아래의 제작자 표기는 동작이 아니므로 넣지 않는다.
- 동작 이름은 그림을 보고 붙인 것이고, 코드에서는 표시용으로만 쓴다.

### 5.3 코드에서의 형태 (예시)

```python
# (이름, bottom, h, [(left, w, dx), ...])
ANIMATIONS = [
    ('대기', 447, 39, [(1, 29, 2), (31, 26, 2), ...]),
    ('걷기', 407, 39, [(8, 26, 0), (37, 27, 0), ...]),
    ...
]

# 그리기
x = pos_x + dx * SCALE * facing   # 제자리 동작은 pos_x = GROUND_X, facing = 1
y = GROUND_Y + h * SCALE / 2
sonic.clip_draw(left, bottom, w, h, x, y, w * SCALE, h * SCALE)
```

- dx는 계산으로 구한 시작값이다. 실제로 보고 몸이 튀는 프레임이 있으면 그 프레임의 dx만 직접 고친다.

## 6. 프로그램 구조

### 6.1 설정 상수 (파일 위쪽에 모아 둔다)

| 이름                   | 값       | 의미                    |
| ---------------------- | -------- | ----------------------- |
| `CANVAS_W, CANVAS_H` | 800, 600 | 창 크기                 |
| `SCALE`              | 2        | 확대 배율               |
| `GROUND_X, GROUND_Y` | 400, 200 | 몸 중심선 x, 발 기준선 y |
| `FRAME_TIME`         | 0.1      | 프레임 간격(초)         |
| `REPEAT_COUNT`       | 5        | 동작별 반복 횟수        |
| `PAUSE_TIME`         | 1.0      | 동작 사이 정지 시간(초) |
| `MOVE_SPEED`         | 동작 이름 → 속도 | 이동 동작의 이동 속도(화면 픽셀/초), F6 표 |
| `MOVE_MARGIN`        | 60       | 방향을 바꾸는 화면 끝 여백 |

### 6.2 상태 변수

| 이름                        | 의미                            |
| --------------------------- | ------------------------------- |
| `anim_index`              | 지금 재생 중인 동작 번호 (0~9)  |
| `frame_index`             | 지금 프레임 번호                |
| `loop_count`              | 지금까지 끝낸 반복 횟수         |
| `paused`, `pause_start` | 정지 중인지, 정지를 시작한 시각 |
| `last_frame_time`         | 마지막으로 프레임을 넘긴 시각   |
| `pos_x`, `facing`         | 캐릭터 몸 중심 x, 보는 방향(1 오른쪽, -1 왼쪽) |
| `last_update_time`        | 마지막으로 `update()`를 부른 시각 (이동 거리 계산용) |

### 6.3 메인 루프 흐름

```
while running:
    handle_events()      # ESC, 창 닫기
    update()             # 시간에 따라 프레임 / 반복 / 정지 / 다음 동작 처리
    draw()               # 지우기 → 캐릭터 → 상태 글자 → 화면 갱신
    delay(0.01)          # CPU를 너무 쓰지 않도록 잠깐 쉼
```

### 6.4 `update()` 규칙

```
dt = 지난 update() 이후 경과 시간 (많아야 FRAME_TIME)
정지 중이면:
    1초가 지났으면 → 다음 동작으로 (anim_index + 1, 끝이면 0), 프레임 0, 반복 0, 정지 해제,
                     위치는 가운데(400), 오른쪽 보기
그렇지 않으면:
    이동 동작이면 → pos_x += 속도 × dt × facing, 화면 끝 여백에 닿으면 facing을 반대로
    FRAME_TIME이 지났으면 → frame_index + 1
        프레임이 끝을 넘으면 → loop_count + 1
            loop_count가 5면 → 마지막 프레임에 머문 채 정지 시작
            아니면 → frame_index = 0
```

## 7. 개발 단계와 커밋 계획

한 번에 다 만들지 않는다. 단계마다 **실행해서 확인한 뒤** 커밋한다.
**한 단계 = 한 커밋**이므로, 아래 30단계를 마치면 커밋이 30개가 된다(최소 20개 기준 충족).
커밋 메시지는 한국어로, 무엇을 왜 했는지 알 수 있게 쓴다.

### 7.1 뼈대 (1~4단계)

| 단계 | 내용 | 확인 방법 |
| ---- | ---- | --------- |
| 1 | 설정 상수를 정의하고 800×600 캔버스를 열고 닫는 뼈대 작성 | 창이 열렸다가 닫힘 |
| 2 | 메인 루프와 `handle_events()` 추가, 창 닫기(`SDL_QUIT`)로 종료 | X 버튼으로 꺼짐 |
| 3 | ESC 키로 종료 | ESC로 꺼짐 |
| 4 | 스프라이트 시트를 `__file__` 기준 경로로 불러오기 | 다른 폴더에서 실행해도 오류 없음 |

### 7.2 1번 동작 재생 (5~10단계)

| 단계 | 내용 | 확인 방법 |
| ---- | ---- | --------- |
| 5 | 1번 동작 첫 프레임을 원본 크기로 `clip_draw` | 대기 자세 한 장이 잘리지 않고 보임 |
| 6 | 2배 확대하고 발 기준선(y=200)에 맞춰 그리기 | 크게 보이고 발이 기준선에 놓임 |
| 7 | 1번 동작 11프레임의 `(left, w)` 데이터 등록 | 프레임 번호를 바꿔 그려 보면 모두 맞게 잘림 |
| 8 | `get_time()` 기준으로 0.1초마다 프레임 넘기기 | 11프레임이 일정한 속도로 돌아감 |
| 9 | 시간 튐 방지 (한 번에 많아야 1프레임만 넘김) | 창을 끌었다 놔도 몰아서 넘어가지 않음 |
| 10 | 1번 동작에 `dx` 보정 추가, 몸 중심을 x=400에 맞춤 | 머리와 몸통이 좌우로 튀지 않음 |

각 단계에서 `(left, w, dx)`를 넣고, 옆 프레임이 잘려 보이지 않는지와 몸이 좌우로 튀지 않는지 확인한다.

## 8. 검증 계획

| 확인할 것           | 방법                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------- |
| 프레임 수와 좌표    | 동작별 프레임 수의 합이 76인지 확인한다. 모든`left + w ≤ 399`, `bottom + h ≤ 525`인지 확인한다. |
| 잘린 프레임         | 각 동작을 직접 보면서 옆 프레임의 일부가 같이 보이지 않는지 확인한다.                                 |
| 5회 반복과 1초 정지 | 상태 표시의 반복 숫자가 1→5로 올라가고, 정지 중에는 마지막 프레임이 유지되는지 본다.                 |
| 전체 순환           | 10번 동작 뒤에`[1/10]`으로 돌아가는지 본다.                                                         |
| 발 위치             | 동작이 바뀌어도 발 높이가 같은지 본다.                                                                |
| 이동                | 이동 동작에서 위치가 매 화면 조금씩 바뀌는지, 끝에서 방향을 바꾸고 그림도 뒤집히는지, 정지 중에는 멈추는지 본다. 제자리 동작은 x=400에 있는지 본다. |
| 좌우 흔들림         | 한 동작을 재생하는 동안 머리와 몸통이 좌우로 튀지 않는지 본다. dx를 0으로 바꿔 그린 것과 비교해 본다. |
| 속도                | 직접 보고 판단한다. 애매하면 다른 값과 비교해 본다.                                                   |
| 종료                | ESC와 창 닫기 둘 다 확인한다.                                                                         |
| 커밋 수             | `git log --oneline --no-merges main..drill09`로 20개 이상인지 확인한다.                             |

프로그램이 실행된다고 해서 프레임이 맞거나 속도가 자연스럽다는 뜻은 아니다. 위 항목은 화면을 직접 보고 확인한다.

## 9. 완료 기준

- [ ] 10종 76프레임이 모두 재생되고, 옆 프레임이 잘려 보이지 않는다.
- [ ] 모든 동작이 정확히 5회 반복된 뒤 1초 동안 마지막 프레임에서 멈춘다.
- [ ] 10번 동작 뒤에 1번 동작으로 돌아가 끊김 없이 계속 반복된다.
- [ ] 캐릭터가 2배 크기로 화면 안에 보이고, 몸이 좌우로 흔들리거나 발 높이가 바뀌지 않는다.
- [ ] 애니메이션 속도가 너무 빠르거나 느리지 않다.
- [ ] 이동 동작(걷기, 가속, 구르기, 달리기, 대시)은 재생하면서 좌우로 부드럽게 움직이고, 화면 끝에서 방향을 바꾸며 화면 밖으로 나가지 않는다.
- [ ] 상태 표시가 실제 재생 상황과 맞다.
- [ ] ESC와 창 닫기로 정상 종료된다.
- [ ] `drill09` 브랜치에 의미 있는 한국어 커밋이 20개 이상 있다. 병합 커밋은 세지 않는다.
